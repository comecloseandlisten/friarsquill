## ЗАДАЧА 1 — Мультиязычная транскрипция

### Проблема
`faster-whisper` в текущей реализации работает с одним языком на весь файл.
Если в видео смешаны языки (RU + EN), он «залипает» на один и транскрибирует остальное криво.

### Архитектурное решение: двухпроходная транскрипция

**Проход 1 — Language Detection (лёгкий)**
- Нарезаем аудио на слайдинговые окна по 30 секунд с шагом 15 сек
- Прогоняем каждое окно через `model.detect_language()` (встроен в faster-whisper, почти бесплатно)
- Строим карту языков: `[(0s-30s, "ru", 0.97), (25s-55s, "en", 0.91), ...]`
- Если найдено >1 языка с вероятностью выше порога (напр. 0.8) — включаем multilingual режим

**Проход 2 — Транскрипция с адаптивным языком**

*Вариант A (без изменений API faster-whisper):*
- Разбиваем аудио на сегменты по обнаруженным языковым зонам через `pydub`
- Транскрибируем каждый сегмент с явным `language="ru"` / `language="en"`
- Склеиваем результаты с правильными таймстемпами

*Вариант B (нативный, предпочтительный):*
- Передаём `language=None` (уже так) + добавляем параметр `multilingual=True` в `model.transcribe()` — это флаг в faster-whisper >= 1.0.3 для code-switching
- Если `info.language_probability < 0.7` → считаем видео мультиязычным и включаем логику A

**Что меняется в коде:**
- `transcriber.py` — добавить `_detect_languages()` и режим `multilingual`
- `config.py` — добавить `multilingual: bool = "auto"` (auto = включается если детектированных языков > 1)
- `pipeline.py` — pass-through параметра

**Ресурсы:** минимальные — language detection по 30-сек окнам на small модели занимает ~0.1с/окно

## ЗАДАЧА 2 — Диаризация спикеров

### Проблема
Транскрипт сейчас — сплошной текст без разметки «кто говорит».
В подкастах, звонках, интервью это критично.

### Архитектурное решение

**Легковесный вариант (без нейросети, рекомендован для старта):**
- Использовать энергетический профиль аудио + паузы для детекции смен спикера
- Параметр `num_speakers` передаётся вручную (если пользователь знает)
- Логика: пауза > N мс после фразы = потенциальная смена спикера; чередовать Speaker A / Speaker B

**Полноценный вариант (pyannote.audio):**
- `pyannote/speaker-diarization-3.1` — SOTA, требует HuggingFace токен
- Запускается отдельным шагом между `extract_audio` и `transcribe`
- Результат: временные метки каждого спикера → мёрджим с Whisper-сегментами по overlap
- Алиасим: SPEAKER_00 → "Менеджер", SPEAKER_01 → "Клиент" (если задан маппинг)

**Что меняется в коде:**
- `config.py` — добавить `diarize: bool = False`, `num_speakers: int | None = None`, `speaker_names: dict = {}`
- Новый файл `diarizer.py` — инкапсулирует pyannote или lightweight-вариант
- `transcriber.py` — добавить `speaker` поле к каждому сегменту
- `formatter.py` — рендер `**Менеджер:** текст` в транскрипте
- `pipeline.py` — добавить опциональный шаг diarize между extract и transcribe

**Автодетекция числа спикеров:** pyannote делает сам если `num_speakers=None`.

## ЗАДАЧА 3 — Режимы саммари

### Проблема
Сейчас один жёстко захардкоженный промпт. Шаблон «Overview / Key Points / Detailed Notes» — универсальный, но ни для чего конкретно. Размытый результат.

### Архитектура: pluggable режимы

Создаём систему режимов: каждый режим = папка `prompts/{mode}/` с двумя файлами:
- `chunk.txt` — промпт для MAP-фазы
- `final.txt` — промпт для REDUCE-фазы
- `config.json` — метадата режима (название, параметры, валидация)

#### Режим 1: `notes` (Конспект) — *заменяет текущий*

**Назначение:** Чистый, структурированный конспект для обучения/обзора.

**Chunk-промпт:** Извлекать только факты, термины, аргументы. Не пересказывать, а кодировать информацию.

**Final-промпт:** Собирать по темам (не по хронологии), дедуплицировать, давать чёткую иерархию: Тема → подпункты → детали. Никакого воды.

**Вывод:** Markdown с H2-темами, строгие bullet-листы, таймкоды.

---

#### Режим 2: `call_check` (Проверка звонка/диалога)

**Назначение:** QA отделов продаж, холодных/горячих звонков. Проверить, что менеджер сказал нужное.

**Конфигурация (передаётся пользователем):**
```json
{
  "required_phrases": ["уточните бюджет", "расскажите о компании", "следующий шаг"],
  "red_flags": ["не знаю", "позвоните завтра", "я уточню у руководства"],
  "scoring_criteria": ["rapport", "needs_discovery", "objection_handling", "closing"]
}
```

**Chunk-промпт:** Фиксировать реплики по спикерам, отмечать обязательные фразы и стоп-слова.

**Final-промпт:** Выдаёт структурированный отчёт:
```
## Оценка звонка
**Итог:** 7.2/10

### Обязательные фразы
✅ "уточните бюджет" — [02:14]
❌ "расскажите о компании" — НЕ СКАЗАНО
✅ "следующий шаг" — [08:47]

### Стоп-слова / Красные флаги
⚠️ "не знаю" — [04:31] — признак неуверенности
⚠️ "я уточню у руководства" — [06:20] — потеря экспертности

### Оценка по критериям
- Rapport building: 8/10
- Выявление потребностей: 6/10
- Работа с возражениями: 7/10
- Закрытие: 8/10

### Рекомендации
...
```

**Что меняется:** `config.py` — добавить `summary_mode`, `call_check_config: dict`

---

#### Режим 3: `factcheck` (Фактологический разбор)

**Назначение:** Проверка фактов в лекциях, новостях, дебатах.

**Chunk-промпт:** Извлекать конкретные утверждения с фактической нагрузкой (числа, даты, имена, события).

**Final-промпт:** Каждое утверждение → уровень верифицируемости (высокий / низкий), источник если очевиден, флаг «требует проверки».

**Вывод:**
```
## Факты из видео

| Утверждение | Таймкод | Статус |
|---|---|---|
| "В 2023 году инфляция составила 7%" | 03:21 | ⚠️ Требует проверки |
| "Компания основана в 1998" | 07:45 | ✅ Верифицируемо |
```

---

#### Режим 4: `tldr` (Краткий пересказ)

**Назначение:** Быстрый вывод — о чём видео за 5 предложений. Для скрининга контента.

**Final-промпт:** Максимум 150 слов. Только суть. Никаких bullet-ов.

---

### Что меняется в коде
- `config.py` — `summary_mode: str = "notes"`, `summary_mode_config: dict = {}`
- `summarizer.py` — выбор папки промптов по `config.summary_mode`; инъекция `summary_mode_config` в промпт через `{{VARIABLE}}`
- Новая папка `backend/prompts/notes/`, `backend/prompts/call_check/`, `backend/prompts/factcheck/`, `backend/prompts/tldr/`
- `main.py` / API — принимать `summary_mode` и `summary_mode_config` от фронтенда

## ЗАДАЧА 4 — Объединённый саммари нескольких видео

### Проблема
Нет возможности обработать пачку видео и получить один итоговый документ.

### Архитектурное решение

**Вариант A: Batch-режим в pipeline**
- Пользователь передаёт массив источников: `sources: list[str]`
- `pipeline.py` обрабатывает каждый файл последовательно (download → extract → transcribe)
- Все транскрипты накапливаются в памяти с метаданными (название видео, длительность)
- Один общий проход summarize по объединённому транскрипту

**Структура объединённого транскрипта:**
```
=== Видео 1: "Звонок с Ивановым" (2026-04-01, 12:34) ===
[0.0s] Привет...
...

=== Видео 2: "Звонок с Петровым" (2026-04-02, 08:15) ===
[0.0s] Добрый день...
```

**Final-промпт в batch-режиме** — дополнительная инструкция: сравнивать между видео, выявлять паттерны, давать сводку по каждому + общий итог.

**Практично для:**
- Проверка нескольких звонков менеджера за неделю → один отчёт
- Серия лекций → единый конспект курса

**Что меняется в коде:**
- `config.py` — `batch_mode: bool = False`
- `pipeline.py` — новый метод `run_batch(sources: list)` → итерирует transcribe на каждом, потом единый `summarize`
- `summarizer.py` — принимает `list[list[dict]]` в batch-режиме (segments per video)
- `formatter.py` — секция per-video + итоговый раздел
- API / `main.py` — новый метод `transcribe_batch`
