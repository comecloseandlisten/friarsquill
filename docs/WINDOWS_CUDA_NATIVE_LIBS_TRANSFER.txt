Перенос подхода к CUDA на Windows (Python + pip wheels: ctranslate2, torch, llama.cpp и т.д.)
Проект: localvideotranscriber / Friar's Quill — рабочий рецепт из backend/main.py
================================================================================

ЗАЧЕМ ЭТО НУЖНО
----------------
Пакеты вроде nvidia-cublas-cu12, nvidia-cudnn-cu12 кладут DLL не в System32 и не
в каталог exe, а в site-packages/nvidia/<пакет>/bin/.

Windows по умолчанию НЕ ищет там зависимости при LoadLibrary из нативного кода
(ctranslate2, torch CUDA, llama.cpp CUDA). В итоге в Python всё «установлено»,
а при первом обращении к GPU — ошибки вида:
  - cublas64_12.dll not found
  - cudnn64_*.dll not found
  - загрузка CUDA DLL падает в произвольном порядке

Решение: зарегистрировать эти каталоги ДО первого import библиотеки, которая
тянет CUDA на уровне C++.


ПОРЯДОК ДЕЙСТВИЙ (КРИТИЧНО — СТРОГО ПО ШАГАМ)
----------------------------------------------
1) В самом начале процесса Python (один раз, до import torch / faster_whisper /
   ctranslate2 / llama_cpp и любых других модулей с CUDA .pyd):

   a) Найти site-packages:
        import sysconfig
        site_packages = sysconfig.get_paths().get("purelib")

   b) Пройти каталог:  <site-packages>/nvidia/*/bin/
      Для каждого существующего bin:
        - os.add_dll_directory(bin)     # Python 3.8+ на Windows
        - собрать список bin_dirs

   c) Добавить все эти bin в начало PATH (через os.environ["PATH"] = ...),
      чтобы транзитивные DLL подхватывались теми загрузчиками, которые смотрят PATH.

2) Опционально, но сильно повышает шанс «всё завелось с первого раза»:
   явная предзагрузка критичных DLL через ctypes.CDLL(полный_путь_к_dll)
   ПОСЛЕ add_dll_directory, ДО import ctranslate2/torch.

   Смысл: как только DLL загружена в процесс, последующие LoadLibrary из
   нативного кода часто получают уже существующий модуль и не зависят от порога
   поиска пути.

   ВАЖНО: имена DLL зависят от версии CUDA / cuDNN в твоих pip-пакетах.
   Список из этого репозитория ориентирован на CUDA 12 + cuDNN 9 (см. main.py).
   В другом проекте открой .../site-packages/nvidia/*/bin/ и сверь реальные
   имена файлов; не копируй список вслепую с другой мажорной версией стека.

3) Только после шагов 1–2 делать:
        import faster_whisper  # пример
        import ctranslate2
        import llama_cpp        # если нужен

4) Отдельный нюанс Windows (из комментария в main.py):
   первый import ctranslate2 лучше выполнять в ГЛАВНОМ потоке процесса, а не
   внутри воркера/потока при первом запросе — иначе возможны зависания/дедлоки
   при ленивой инициализации нативного рантайма.


ОБНАРУЖЕНИЕ GPU (для UI / логики «cuda или cpu»)
-------------------------------------------------
В этом проекте два уровня:

  A) Инфа для пользователя (имя карты, VRAM):
     backend/calibrate.py → detect_gpu_info()
     Сначала pynvml (если есть), иначе subprocess nvidia-smi.
     Это не гарантирует, что ctranslate2 увидит те же DLL — это про драйвер.

  B) Реально «есть ли CUDA для faster-whisper»:
     backend/transcriber.py — device=auto через
     ctranslate2.get_cuda_device_count()
     То есть после правильной регистрации DLL; иначе будет 0 и тихий CPU.


ЧТО НЕ ЗАБЫТЬ В ДРУГОМ ПРОЕКТЕ
-------------------------------
- Регистрацию DLL вынести в ОДИН модуль, который импортируется САМЫМ ПЕРВЫМ
  (или вызвать функцию вручную до любых тяжёлых import).
- Не полагаться на то, что «pip всё прописал»: для нативных колёс это часто ложь.
- Версии nvidia-*-cu12 в pip должны соответствовать тому, с чем собран
  ctranslate2 / torch (микс разных мажоров CUDA — отдельный источник боли).
- Если приложение не консольное, а GUI/сервис — всё равно тот же порядок:
  регистрация до первого CUDA import в том же процессе.


КОРОТКАЯ ВЫЖИМКА ДЛЯ КОЛЛЕГИ
----------------------------
«На Windows до import torch/ctranslate2/llama_cpp: обойти site-packages/nvidia,
на каждый .../bin вызвать add_dll_directory, prepend в PATH, по желанию
ctypes.CDLL ключевых cublas/cudnn из этих bin. Потом уже import. Имена DLL
сверять с установленной версией CUDA/cuDNN в site-packages, не копипастить
чужой список вслепую.»


ССЫЛКА НА КОД В ЭТОМ РЕПОЗИТОРИИ
--------------------------------
Реализация: backend/main.py — функция _register_nvidia_dll_dirs(), вызов
сразу под определением функции, строки ~13–99 (до import faster_whisper).
